# ЧекСкан для Android

Нативное приложение на Java: сканирование QR-кодов чеков камерой, загрузка через proverkacheka.com, локальная история и статистика цен. Android 7.0 и новее.

Откройте корневую папку проекта в Android Studio и соберите приложение. Токен сервиса «Проверка чека» можно задать при сборке одним из способов:

- переменная окружения `FNS_TOKEN` (она должна быть доступна процессу Gradle, в том числе при запуске из Android Studio);
- строка `fns.token=ваш_токен` в файле `local.properties`. Этот файл исключён из Git. Если в нём уже указан `sdk.dir`, сохраните эту строку.

Переменная окружения имеет приоритет перед `local.properties`. После изменения токена пересоберите приложение. Также можно ввести содержимое QR-кода вручную на главном экране.

Токен, заданный при сборке, попадает в APK и может быть извлечён. Для публичного распространения используйте сервер-посредник и не встраивайте общий токен в приложение. Чеки хранятся только на устройстве; удаление приложения удаляет данные.

## Структура

- `domain` — модели, контракты репозитория и сервиса, сценарии импорта и получения данных.
- `data` — клиент сервиса, SQLite и реализация репозитория. Схема прежней локальной базы сохранена.
- `presentation` — отдельные фрагменты экранов и `ReceiptViewModel`; `MainActivity` отвечает за навигацию и результат сканирования.
- `di` — создание зависимостей приложения.

Сеть и запросы к базе выполняются в рабочем потоке. Модульные тесты сценария импорта запускаются задачей `testDebugUnitTest`.

## Release APK

Задача `assembleRelease` включает оптимизацию R8 и удаление неиспользуемых ресурсов. Для подписи локально используются `release-key.jks` и `release-signing.properties` в папке проекта; оба файла исключены из Git. Сохраните их в надёжном месте: для обновления приложения на уже установленных устройствах потребуется тот же ключ. Если файлов нет, Gradle создаст неподписанный APK, который нужно подписать перед установкой.
